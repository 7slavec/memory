# Norka: карта сервиса и правила системы

Обновлено: 27 сентября 2026. Это точка входа для дизайна и разработки.
Документ разделяет **решения пользователя**, **предложения** и **текущее состояние кода**. Наличие правила здесь не означает, что все экраны уже ему соответствуют.

## 1. Карта сервиса

| Сценарий | Путь пользователя | Где искать реализацию |
|---|---|---|
| Первый запуск | приветствие → вход / регистрация / локальный режим → приложение | `Memory/MemoryApp.swift`, `Memory/AccountView.swift` |
| Главная | сфера → слушает → обрабатывает → одна запись или список результатов | `Features/Capture/QuickCaptureCard.swift`, `VoiceInputController.swift`, `VoiceInterpretation.swift`, `ContentView.swift` |
| Ручное создание | поле → текст и подсказки → отправка или раскрытие полного редактора | `Features/Capture/QuickCaptureCard.swift`, `ItemEditorView.swift`; сохранение — `ContentView.addItem` |
| Несколько записей | автосоздание валидных результатов → компактный список → редактор отдельной записи → список → готово / сохранить изменения / отменить создание | `VoiceBatchReviewView.swift`, `Features/VoiceReview/VoiceBatchReviewSession.swift`; persistence — `ContentView` |
| Все записи | поиск → Просрочено / Сегодня / Завтра / На неделе / Позже → редактор | `ContentView`: `allItemsContent`, `AllItemsGroup`, `taskRows` |
| Входящие | все записи → входящие без срока → редактор → назад | `ContentView`: `mobileInboxContent`, `desktopInboxContent` |
| Профиль | аватар и почта / локальный профиль → настройки / вход / архив / Voice Lab | iPhone: `ContentView.mobileProfileContent`; Mac: `AccountView.desktopProfileView` |
| Архив | профиль на iPhone / боковая панель Mac → выполненные и прошедшие события → запись | `ContentView`: `mobileArchiveContent`, `desktopArchiveContent`, `completedItems` |
| Редактор | заголовок, описание, тип, расписание, уведомления, действия → сохранить / назад | `ItemEditorView.swift` |
| Voice Lab | параметры разбора → примеры → исправления / проверки | `VoiceLabView.swift`, `VoiceLabStore.swift` |

Пути без префикса в таблице относятся к `Memory/`.

### Обязательные состояния сценариев

- Ввод: пусто без фокуса, пусто с фокусом, текст, длинный текст, клавиатура, раскрытие и возврат, отмена, ошибка сохранения.
- Голос: покой, слушает, обработка, одна / несколько записей, неопределённость, пустой результат, ошибка, отмена, повторная запись. Метаданные одной записи не распространяются на всю многосоставную фразу.
- Списки: пусто, есть записи, поиск без результатов, длинные названия, события через несколько дней, большие списки.
- Профиль: локальный / авторизованный, нет сети, синхронизация / ошибка, системный запрет уведомлений, общий переключатель выключен.
- Редактор: новая / существующая запись, напоминание / событие, без описания, без срока, начало без окончания, период, неверный период, несохранённые изменения.
- Каждая визуальная проверка указывает платформу, тему, размер окна/экрана и размер текста. Не считать все сочетания проверенными автоматически.

## 2. Принятые дизайнером правила

### Семейства компонентов

| Семейство | Контракт | Реализация сейчас |
|---|---|---|
| Шапка | Основная / внутренняя; одинаковая высота внутри платформы, содержимое центрировано; один владелец навигации | Ещё распределена между `ContentView`, редактором и профилем |
| Сфера | Покой / слушает / обрабатывает; не меняет структуру страницы | `DesignSystem/Components/GlassVoiceOrb.swift` |
| Карточка записи | Только напоминание / событие; заголовок, описание и расписание при наличии; никаких больших review-вариантов | `DesignSystem/Components/MemoryItemRow.swift`; `Features/Home/HomePriorityCard.swift` — временное исключение, подлежит объединению |
| Поле создания | Общий вид во всех точках входа, состояние фокуса и текста, необязательная строка подсказок | `Features/Capture/QuickCaptureCard.swift`; пока содержит и orchestration, нужен следующий этап разделения |
| Поиск | Единая основа поля, фокус, значение, очистка | Копии в `ContentView`, объединение запланировано |
| Заголовок группы | Иконка + текст + количество | `DesignSystem/Components/MemorySectionHeader.swift` |
| Кнопка | Текстовая с необязательной иконкой / иконочная; ограниченные S/M/L с закреплённым назначением | Общая реализация ещё не создана; точные размеры не согласованы |
| Плашка | По содержимому, общая высота/типографика, необязательная иконка и дополнительное действие | `DesignSystem/Components/EntryChips.swift`; объединение внешней основы ещё предстоит |
| Строка настройки | Общая основа, необязательная иконка; справа переключатель / значение выбора / переход | Пока отдельные реализации профиля и редактора |
| Аватар | Один компонент, размеры для шапки, профиля, панели Mac | Ещё встроен в экраны |
| Календарь | Единая логика выбора и открытия во всех точках одной платформы; необязательное действие не создаёт новый календарь | `DesignSystem/Schedule/MemoryCalendarPicker.swift`, `MobileSchedulePickerSheet.swift`; визуальная переработка ещё не выполнена |
| Выбор времени | Отдельное семейство, единая семантика выбора, закрытия и ограничения диапазона | `DesignSystem/Schedule/MemoryTimePicker.swift`, мобильная часть в `MobileSchedulePickerSheet.swift` |

Не превращать разные элементы управления в один компонент с десятками boolean. Для взаимоисключающих вариантов использовать тип варианта; для иконки/описания — необязательное содержимое. Переключатель, переход и выбор имеют разные действия и accessibility-роли при общей визуальной основе.

### Текст и композиция

- Роли: Large title в записи; H1 — страницы и текст под сферой; H2 — разделы (почта профиля пока кандидат); Body — содержимое; Caption — короткие вторичные обозначения.
- Численные размеры, насыщенность и межстрочные интервалы ещё требуют визуального согласования, включая Dynamic Type.
- Поясняющие подзаголовки отсутствуют по умолчанию. Исключения: ошибка, последствия опасного действия или действительно непонятный выбор. Описание пользовательской записи — содержимое, не служебная подсказка.
- Даты — русские, сокращённый месяц в компактных контролах, год нужен при отличии от текущего. Для многодневного периода должно быть видно окончание, а не только его час.
- Дата/время не занимают пустое место при отсутствии. Текущее «Без срока» в карточке — открытое несоответствие, не принятый вариант.

### Цвет, размеры и состояния

- Цветовые роли: фон, поверхность, граница, основной/вторичный текст, акцент, событие, опасное действие. Значения выбираются отдельно для светлой/тёмной темы.
- Фиолетовый — расписание; золотистый — тип/поверхность события, не специальный цвет окончания.
- Стандартное / нажатое / недоступное состояние; Mac дополнительно hover и keyboard focus. Selected/loading — только где имеют смысл. Нажатие не меняет геометрию.
- Визуальная компактность не уменьшает область нажатия iPhone ниже 44 × 44 pt. На Mac правила плотности могут отличаться, но одинаковые элементы одной платформы имеют одинаковый размер.
- Удаление и выход — варианты общей кнопки, а не новые композиции.
- Никаких новых стилей без явного отличия задачи, которого не покрывают существующие варианты.

### Предложенные, ещё не утверждённые числа

- Шаг отступов 4 pt; рабочая шкала 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48. Иные значения допустимы после определения роли, не ради локального исправления.
- Внутри связанной группы отступ меньше, чем до соседней группы. Названия токенов должны отражать роль: controlGap, cardInset, sectionGap, pageInset, а не случайный номер.
- Контраст обычного текста: ориентир 4.5:1; крупного — 3:1 по WCAG. Это критерий проверки, не заявление о текущем соответствии Norka. Проверять составной фон, включая прозрачность.

## 3. Календарь и время: контракт до переработки

**Принято:** это переиспользуемые компоненты; общие паттерны во всех местах, допустим платформенный контейнер (iPhone sheet / Mac overlay), но не разная семантика одного действия.

**Сохраняем при структурном переносе:** существующее применение даты/времени. Мобильная дата закрывается по выбору; исчезновение мобильного picker применяет текущее значение; Mac date меняет Binding сразу и имеет «Готово»; Mac time закрывается после выбора/применения. Эти различия не объявлены окончательным дизайном.

**Нужно согласовать перед визуальной переделкой:** закрытие по выбору или явное подтверждение; применение времени при закрытии; значение нажатия вне окна/свайпа; нужен ли «Сегодня»; доступность очистки для начала и окончания.

**Данные:** текущий `Item` хранит `dueDate: Date?` и `endDate: Date?`, а не отдельно необязательные дату и час. Раздельные строки редактора не реализуют «день без времени». Пользователь ранее запросил независимые поля: это незакрытая задача модели/синхронизации, её нельзя имитировать скрытым 00:00 или мигрировать попутно с дизайном.

Проверки: високосный февраль, месяц на 6 недель, переход года, изменение даты сохраняет время, изменение часа сохраняет день, необязательное окончание, некорректный период, повторное открытие, закрытие без выбора, русская локаль, часовой пояс/DST, клавиатурное управление Mac.

## 4. Структура кода и владельцы

Текущий первый шаг, не завершённая миграция:

```text
Memory/
  DesignSystem/
    Components/     карточки, плашки, сфера, поверхности, заголовок группы
    Schedule/       календарь, время, цель выбора, мобильная оболочка
  Features/
    Capture/        ввод и обратная связь создания
    Home/           специфичная композиция главной
    VoiceReview/    состояние черновика нескольких записей
  Domain/
    Interpretation/ определение типа записи, без SwiftUI
  ContentView.swift оставшаяся корневая композиция и временно команды данных
  ItemEditorView.swift
  AccountView.swift
  MemoryTheme.swift
  …                 существующие модели/сервисы остаются на месте до своей итерации
```

Следующие границы, вводить только при миграции соответствующего сценария:

- App: маршрут, платформа, зависимости. Один владелец активной страницы.
- Features: собственный черновик/фокус/состояния экрана; не захватывать навигацию родителя скрыто.
- Domain: правила типа, периода, группировки и валидации; тестировать без UI.
- Services: команды сохранения → планирование уведомлений → синхронизация после успешного сохранения. Не переносить несвязанные сервисы только ради папок.
- DesignSystem: значения и callback; без сетевых запросов, сохранения и разрешений.

Ограничение длины файла — сигнал для ревью, не повод разрезать одно состояние на произвольные extension. Перед переносом назвать владельца состояния и зависимые вызовы. Не менять идентичность View и локальные @State в механическом коммите.

## 5. Рабочий цикл

1. Выбрать один сценарий и прочитать его участок по карте.
2. Записать критерии приёмки и различия с нынешним поведением. Разделить решения пользователя и предложения.
3. Сделать точку возврата. Механический перенос и функциональные изменения — разные коммиты.
4. Использовать существующий компонент. Если не подходит — объяснить конкретный недостающий вариант.
5. Проверить исходные и конечные состояния, повтор, отмену и ошибки. Обновить минимальный регрессионный тест.
6. Сборки обеих платформ, применимые тесты, визуальные проверки затронутых размеров/тем. Честно отметить непроверенное.
7. После проверок — один небольшой коммит, краткая запись результата и открытых рисков. Установка на устройства — отдельное действие, не следствие успешной компиляции.

### Воспроизводимая локальная проверка

`bash scripts/verify-local.sh` — Mac unit tests и компиляция iOS. `--ui` добавляет существующий Mac UI-тест review → первый редактор → назад → второй редактор → сохранить.

Скрипт использует отдельные каталоги результатов, не чистит кэш, не устанавливает приложение и не публикует серверные функции. Тест UI использует `--uitest-voice-review`, память вместо пользовательской БД и отключённый облачный клиент. Закройте обычное окно Norka перед UI-прогоном, если single-instance защита мешает тестовому запуску. Не закрывать пользовательское приложение автоматически с потерей черновика.

Сборки не заменяют: реальную диктовку, доставку уведомлений на устройстве, синхронизацию двух устройств, ручную проверку клавиатуры iPhone, VoiceOver и измерение плавности.

## 6. Источники и скиллы

- [Apple UI Design Dos and Don’ts](https://developer.apple.com/design/tips/) — область нажатия, читаемость, группировка.
- [WCAG contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) — измеримые ориентиры контраста; адаптировать к нативному UI.
- Локальный `mobile-product-development` — регрессионные сценарии Norka, focus/keyboard/composition.
- [SwiftUI Expert](https://github.com/AvdLee/SwiftUI-Agent-Skill), установленная ревизия `b24e68a965dc4b5bd2cc41dc60c094a26a9379ce` — дополнительный справочник для следующих задач, не замена продуктовым решениям и документации SDK.
- UI UX Pro Max рассмотрен, не установлен: генерация новых стилей сейчас не требуется. Популярность не доказывает совместимость с Norka.

Не переносить в скилл всю карту проекта: этот документ версионируется вместе с кодом. В скилле остаются маршрутизация и проверенные уроки.
