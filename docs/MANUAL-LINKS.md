# Ручные связи — первая итерация, 28 сентября 2026

## Контракт

Существующая запись → компактная плашка связи рядом с типом → попап → «+» → выбрать активную запись.
Связь симметричная: напоминание ↔ напоминание, напоминание ↔ событие, событие ↔ событие.
Карточка в попапе открывает обычный редактор. Назад возвращает к предыдущему редактору.
Снятие связи не удаляет записи. Выполнение и сроки независимы.

- Самосвязи, дубликаты, удалённые записи и записи другого аккаунта исключены.
- Добавлять можно только активные записи, включая входящие и просроченные напоминания. Выполненные и прошедшие события из архива не предлагаются. Существующая связь с архивной записью остаётся видимой и может быть снята.
- На карточке связанной записи — та же плашка. Для пары только значок; число появляется при двух и более соседях и включает текущую запись (3, 4…). Это прямые связи, не автоматически объединяемая транзитивная группа.
- «Разорвать все связи» после подтверждения снимает только связи текущей записи. Остальные связи и сами записи не меняются.
- Открытие/закрытие попапа не пересоздаёт редактор и не сбрасывает черновик. iPhone: нижний лист; Mac: popover в текущем окне.
- Черновик сначала нужно создать; batch-review не меняет своей семантики сохранения/отмены.
- При несохранённых правках перед переходом предлагаются сохранение, отказ от правок или отмена.
- При ошибке сохранения редактор не закрывается и удерживает текст.
- В этой версии нет типов «подготовка / после», относительных сроков, автоматических связей из речи и каскадного завершения.
- Независимый час (запись с датой без времени) остаётся отдельной миграцией; здесь `Item.dueDate` не изменён.

## Сохранение и совместимость

Идентификатор связи — два отсортированных UUID. Обратная связь получает тот же ID.
Удаление — tombstone, а не физическое удаление: старое офлайн-устройство не должно вернуть снятую связь.
При равном времени побеждает tombstone. Новая связь после снятия обновляет тот же объект.
Локальные связи переходят к первому аккаунту только вместе с обеими записями.
Удаление записи помечает её связи, но не меняет вторую запись.

`Item` не меняется; в локальную схему добавляется отдельная сущность. Тест миграции открывает
старое дисковое хранилище `Item` новой схемой, проверяет содержимое и повторное открытие связей.
Это проверка фикстуры, не доказательство совместимости со всеми возможными реальными базами.

Серверная миграция подготовлена, но её применение требует отдельного разрешения и проверки.
До появления таблицы обычные записи продолжают синхронизироваться; раздел связей сообщает,
что синхронизация связей не подключена. Связи не теряются локально.
Не считать облачный сценарий проверенным только по сборке или локальным тестам.
