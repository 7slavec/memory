# Norka Events v1 — продуктовая спецификация

Статус: ручной сценарий реализован
Дата: 22 сентября 2026

## Цель

Добавить событие как второй пользовательский тип записи, сохранив скорость обычного напоминания. Событие занимает временной диапазон, не имеет галочки выполнения и живёт в том же хронологическом списке.

## Модель

- `reminder`: действие, которое нужно выполнить; может быть без срока или иметь один срок.
- `event`: запись с обязательным началом; окончание добавляется только при необходимости.
- В хранилище используется общая запись с типом `reminder/event`.
- Для обратной совместимости все существующие записи автоматически считаются напоминаниями.
- Текущее поле `dueDate` остаётся сроком напоминания и становится началом события; для события добавляется `endDate`.
- Уведомления события считаются относительно его начала.

## Карточки в общем списке

### Напоминание

- Круг выполнения.
- Заголовок.
- Срок и состояние уведомления.
- После выполнения уходит в архив.

### Событие

- Золотистая подложка вместо круга выполнения и отдельной иконки типа.
- Заголовок.
- Диапазон времени: `19:00–21:00`.
- Во время события статус `Сейчас`.
- После окончания событие считается прошедшим, но не выполненным.

Карточки отличаются достаточно, чтобы тип был понятен без отдельной крупной подписи «Событие».

## Новый быстрый ввод с клавиатуры

### Базовое состояние

- Поле ввода и кнопка отправки остаются главным сценарием.
- Тип по умолчанию выбирается в профиле: напоминание или событие.
- Постоянная строка `Без срока / Сегодня / Завтра` удаляется.
- Рядом с активным полем остаётся только компактный chevron подробного редактирования.

### Подробное редактирование

Chevron открывает стандартную внутреннюю страницу записи. Там доступны тип,
дата или диапазон, описание и уведомления. Отдельного меню параметров поверх
клавиатуры нет.

После выбора под текстом появляется только фактически заданное резюме:

- `Сегодня · 20:00`;
- `Событие · Пн, 19:00–21:00`;
- `Без срока` не показывается, потому что это нормальное пустое состояние.

Если система распознала тип, отличный от выбранного по умолчанию, рядом со
временем появляется компактная удаляемая подсказка `Событие` или
`Напоминание`. Удаление возвращает тип по умолчанию.

Выбор даты и диапазона открывается в компактной системной панели. Клавиатура скрывается один раз осознанно и не прыгает; после закрытия панели фокус возвращается в основное поле, если пользователь ещё не отправил запись.

### Ручное событие

1. Пользователь набирает название.
2. При необходимости открывает подробный редактор chevron-кнопкой и выбирает `Событие`.
3. Norka предлагает начало. Окончание пользователь добавляет отдельной кнопкой, если оно действительно известно.
4. Пользователь отправляет запись стрелкой или клавишей Done.
5. Если пользователь добавил окончание и диапазон некорректен, запись не создаётся и подсвечивается только проблемное поле.

## Голосовой ввод

Сохраняется текущая композиция сферы и бесшовное состояние:

`idle → listening → processing → saved | clarification | preview | error`

### Один результат с высокой уверенностью

- `Напомни завтра отправить отчёт` → напоминание создаётся сразу.
- `В понедельник вебинар с семи до девяти` → событие создаётся сразу.
- После сохранения показывается короткое уведомление с типом и временем.

### Событие без окончания

Фраза `В понедельник вебинар в семь` может быть сохранена как событие только с началом. Norka не заставляет пользователя придумывать окончание и не задаёт лишний уточняющий вопрос.

### Неясный тип

Если одинаково вероятны напоминание и событие, под сферой появляется один выбор `Напоминание / Событие`. Полный экран подтверждения не используется.

### Несколько результатов

Фраза `В понедельник вебинар с семи до девяти, а до воскресенья отправить заявку` создаёт черновик из двух карточек:

1. Событие `Вебинар`, пн 19:00–21:00.
2. Напоминание `Отправить заявку`, срок — воскресенье.

Несколько записей всегда показываются в компактном предварительном просмотре перед сохранением. Пользователь может удалить одну карточку или изменить её тип. Автоматическое сохранение нескольких сущностей без просмотра не используется в v1.

## Состояния интерфейса

| Состояние | Что видно | Доступное действие |
|---|---|---|
| Пустой ввод | Минималистичное поле | Печатать или говорить |
| Текст напоминания | Две строки текста, динамическое резюме срока | Отправить или открыть параметры |
| Текст события | Тип и диапазон под текстом | Отправить или изменить диапазон |
| Подробный редактор | Внутренняя страница записи | Выбрать тип, дату, описание, уведомление |
| Голосовая запись | Сфера и живой транскрипт | Остановить запись |
| Обработка | Сфера и короткий статус | Дождаться результата |
| Уточнение | Один вопрос и 2–3 ответа | Выбрать только недостающее значение |
| Несколько записей | Небольшой стек черновиков | Сохранить всё или поправить карточку |
| Ошибка | Текущая композиция без сброса полезного текста | Повторить или сохранить вручную |

## iPhone и Mac

- Общая модель и правила интерпретации одинаковы.
- На iPhone chevron открывает внутреннюю страницу редактора.
- На Mac редактор события использует рабочую область, а не отдельное окно.
- На обеих платформах простое напоминание создаётся без обязательного выбора типа.

## Безопасная последовательность реализации

1. Добавить тип записи и `endDate` с миграцией существующих данных.
2. Обновить локальную модель, Supabase и синхронизацию.
3. Добавить ручной редактор события на iPhone и Mac.
4. Добавить карточки события и правила хронологического списка.
5. Убрать постоянные быстрые даты и добавить chevron подробного редактирования.
6. Добавить тесты миграции, диапазона и старых напоминаний.
7. Только после ручного прогона расширить DeepSeek-контракт одним результатом `reminder/event`.
8. После Voice Lab-корпуса включить предварительный просмотр нескольких результатов.

## Регрессионный минимум

- Старое напоминание открывается и сохраняется без изменения данных.
- Напоминание без срока создаётся одним нажатием.
- Клавиатура не перекрывает composer и не прыгает при повторном открытии параметров.
- Событие нельзя сохранить без начала.
- Если окончание добавлено, оно всегда позже начала.
- Голосовая запись не показывает промежуточный текст в обычном composer.
- Уведомления напоминаний продолжают работать как раньше.
- Синхронизация между iPhone и Mac не превращает событие в напоминание.

## Жизненный цикл

Событие остаётся в истории текущего дня, включая время после окончания. В архив оно переносится автоматически с начала следующего дня после даты окончания, а если окончания нет — после дня начала.
